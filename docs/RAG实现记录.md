## 🎯 数据重建（2026-11-01 下午，本轮最重要的一次改动）

前面所有优化的瓶颈都不在算法，在**数据**。本轮把 `paths.jsonl` 的
`name` 和 `aliases` 整体重建了。

### 根因

两个独立子智能体分别指出：

**1. 424/427 条 alias 是模板拼接**，净贡献 **0 条**
（救回 3 条、弄坏 3 条，正好抵消），却吃掉 **64.2% 的索引文本**。

```
"儿子的微信" / "怎么儿子的微信" / "我要儿子的微信" / "帮我儿子的微信"
```

**2. name 不是任务名，是「第一个可点按钮」**
—— 114/120 条（95.0%）满足 `name == steps[0].target 去掉动词`。

后果：111/120 条（92.5%）老人根本不会这么说。

| 类型 | 条数 | 例子 |
|---|---|---|
| 界面控件值（根本不是任务名） | 23 | `待支付` `周六` `居民身份证` `下一步` `马上看看` |
| 专有名词/品牌 | 11 | `粤税通` `穗好办` `关怀版` `微警认证` |
| 公文黑话 | 72 | `门诊缴费` `社会保险参保证明查询` `城乡居民医保费清缴` |
| 真口语 | **9（7.5%）** | `转账` `红包` `打车` `公积金` |

**3. 8 条链 steps 自循环**：`gov.insurance_code` 三步全是「点医保电子凭证」，
`hospital.add_patient` 是「添加就诊人→我的家人→添加就诊人」。不可执行。

> ⚠️ **修复后仍有 2 条残留问题**（独立验证指出）：
> - `hospital.add_patient`：去重后剩「添加就诊人→我的家人」，**顺序仍反**
>   （真实路径应是先进「我的家人」再「添加就诊人」）
> - `gov.elder_mode`：剩「关怀版→长辈版」，但这两个是**同一功能的不同叫法**，
>   语义仍循环
>
> 这两条**没有可靠依据判断正确顺序**，故保留原样并标注，
> 不猜一个顺序写进去。

**4. 6 条 `pick_*` 选项页把「选项值」当任务名**：
`神经医学科`（实为 22 个科室的选择页）、`科室`（实为时段选择）、
`医生袁嘉蔚`、`周六`、`上午`、`居民身份证`。

### 改法（`tools/rebuild_paths.py`）

- name 改「动作+对象」，用老人能听懂的话（44/120 条改名）
- aliases 删光模板，换成真实口语（427 → 252 条）
- 修 8 条自循环 steps
- 补 `app` 字段（原来 120/120 全空）

**独立性保证与诚实的泄漏披露**（经独立验证修正）：

新 name/aliases 独立构思，来源是对 `steps[].target` 的理解和老人日常说话的常识，
**没有照抄任何评测集**。但必须如实说明：

- 改写**前**：原集 68 条 query 与 name/alias **0 条完全相等**
- 改写**后**：**6 条完全相等**（都在盲写集里，属自然表达重合）
- 另有 **21/68 条（30.9%）是子串关系**（如 query「想找律师问问」⊃ alias「找律师」）
- 26/68 条编辑距离 ≤2

> ⚠️ 早先版本本文档写「把 44 处完全相同的改到只剩 5 处」，**这是错的**：
> 实际是改写**引入**了 6 处精确匹配，不是消除。该数字由独立验证指出并已更正。
> 根因是 `rebuild_paths.py` 的泄漏自检只查「完全相等」，漏掉了子串与近似，
> 现已改为三档检查（完全相等 / 子串 / 编辑距离≤2）。

**净化实验**（证明主体增益真实）：
删掉全部 64 条「与任一评测 query 有逐字重叠」的 alias 后重跑：

| 评测集 | 净化前 R@5 | **净化后 R@5** | 变化 |
|---|---|---|---|
| 盲写集（170） | 87.6% | **85.3%** | -2.3 |
| 留出集（52） | 86.5% | **84.6%** | -1.9 |

**去掉全部泄漏指纹后仍有 85%+**，说明主体增益来自真实的语义覆盖，不是背答案。

## 四、域外拒识（返工新增）

初版 hybrid 模式直接丢掉了 `min_score` 过滤，导致：

```
"我想买火车票"  -> 返回 3 条，分数全是 RRF 地板分 0.016
"今天天气怎么样" -> 返回 3 条，全是地板分
```

连带 MCP 的 `search_guide` 里 `"" if hits else "没有匹配到标准路径"` 永久失效。

**返工过程（三轮，值得记录）**：

| 轮次 | 方案 | 结果 |
|---|---|---|
| 1 | 向量相似度 >= 0.45 | 域外仍误召 3/8。「我要打游戏」→ map.taxi 0.524，比正确的「给孙子点零花钱」0.535 只低 0.011 |
| 2 | 加「字面必须有交集」硬门槛 | 域外 0/8，但**砍掉 14 条正确答案**（「给他转点钱」→转账 0.770 都被砍） |
| 3 | **绝对阈值 + 相对领先** | 域外 0/8，原集 79.4%，留出集 71.2% ✅ |

第三轮的判据：

```python
top_sim >= 0.55  and  (top1 - top5) >= 0.02
```

**为什么这样有效**：域外查询的问题不是分数低，而是**分数平**——
一堆 0.41–0.53 挤在一起，说明模型对这句话没有任何偏好，就该拒识。
域内查询通常 top1 明显领先。

参数可调：`NEXTTAP_VECTOR_MIN` / `NEXTTAP_VECTOR_GAP`。
调参曲线（域外误召 / 原集 / 留出集）：

| MIN | GAP | 域外误召 | 原集 R@5 | 留出 R@5 |
|---|---|---|---|---|
| 0.50 | 0.02 | 3/8 | 80.9% | 76.9% |
| 0.50 | 0.05 | 1/8 | 76.5% | 75.0% |
| **0.55** | **0.02** | **0/8** | **79.4%** | **71.2%** |
| 0.55 | 0.05 | 0/8 | 76.5% | 71.2% |
| 0.60 | 0.02 | 0/8 | 73.5% | 63.5% |

选了 0.55/0.02：域外全拒，召回损失最小。

## 五、技术路线

### 为什么用本地 ONNX 而不是云端

原计划走云端 embedding（技术文档 2.3 就是这么写的），但：

- DeepSeek 的 key **调不通**智谱/通义的 embedding 接口（服务商不同，401）
- 评审意见 §三 建议「embedding + rerank 换 onnxruntime 后端，内存可砍一半」

**实际：`fastembed` + `BAAI/bge-small-zh-v1.5`（512 维，ONNX，约 90MB）**

> ⚠️ **技术文档 2.3 写的「Embedding 上云」与实现矛盾，需要改。**

### 三阶检索

```
query
  ├─ 词面召回（_score）：去填充词 + 同义词扩展 + 二字组重合度
  ├─ 向量召回（_VectorIndex）：bge-small-zh 余弦相似度
  ├─ 域外拒识：绝对阈值 + 相对领先
  ├─ RRF 融合：score = Σ 1/(60+rank)
  └─ rerank（可选，仅离线）
```

**为什么用 RRF**：词面是 0–1 相似度、向量是余弦距离，量纲不同，
直接加权要归一化且权重难调；RRF 只看排名，无需调参。

### 开关与降级

| `NEXTTAP_RETRIEVAL` | 行为 |
|---|---|
| `lexical` | 只走词面 |
| `hybrid` | 词面 + 向量 + RRF（**默认，线上用这个**） |
| `hybrid_rerank` | 再叠 rerank（离线消融用） |

`fastembed` 缺失或加载失败 → 自动退回纯词面，不抛异常（已模拟 ImportError 验证）。
