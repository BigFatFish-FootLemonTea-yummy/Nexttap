# 部署指南

> 单机 Docker Compose 部署：Nginx（静态 + 反代） + FastAPI（OCR + LLM）
> 目标机器：国内 2C4G 轻量应用服务器，纯 CPU，无 GPU

---

## 一、架构

```
                 公网 80
                    │
            ┌───────▼────────┐
            │  web (nginx)   │  静态文件 + 反向代理
            └───┬────────┬───┘
                │        │
      / 静态资源 │        │ /api/*  /health
                │        │
          dist/  │   ┌────▼─────┐
                 └──▶│ api      │  FastAPI + RapidOCR
                     │ :8000    │  （不对外暴露端口）
                     └────┬─────┘
                          │
                    ./server/data
```

**为什么同域**：分域必然引入 CORS 与 Cookie 调试成本。同域下前端只写相对路径 `/api`，`client.ts` 里的 `VITE_API_BASE` 留空即可。

**为什么 api 不暴露端口**：只让 Nginx 转发，避免 8000 直接暴露到公网被刷。

## 二、服务器准备

### 1. 装 Docker

```bash
# Ubuntu / Debian
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 验证
docker --version
docker compose version
```

> **国内机器**：`get.docker.com` 可能很慢，用阿里云镜像：
> ```bash
> curl -fsSL https://get.docker.com | sh -s -- --mirror Aliyun
> ```

### 2. 配镜像加速（国内必做，否则拉不动基础镜像）

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://mirror.ccs.tencentyun.com"
  ]
}
EOF
sudo systemctl restart docker
```

### 3. 装 git 并拉代码

```bash
sudo apt install -y git
git clone https://github.com/BigFatFish-FootLemonTea-yummy/Nexttap.git nexttap
cd nexttap
```

## 三、配置

### 1. 写 `.env`

```bash
cp .env.example .env
vim .env
```

填三项：

```ini
LLM_API_KEY=sk-你的key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

> ⚠️ `.env` 已在 `.gitignore` 里，**绝对不能提交**。

### 2. 构建并启动

```bash
docker compose up -d --build
```

首次构建约 5–10 分钟（要装 rapidocr + onnxruntime + opencv，约 300MB）。

### 3. 看状态

```bash
docker compose ps
docker compose logs -f api
```

等日志出现 `OCR 预热完成` 才算真正就绪（约 30–60 秒）。

浏览器打开 `http://<服务器公网IP>/` 应该能看到上传页。

## 五、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `docker compose up` 卡在拉镜像 | 没配镜像加速 | 见 §二.2 |
| api 容器反复重启 | `.env` 没填或 key 无效 | `docker compose logs api` 看报错 |
| 502 Bad Gateway | api 还没起好 | 等 OCR 预热完成，`docker compose logs -f api` |
| 上传大图报 413 | Nginx 限制 | `nginx.conf` 里 `client_max_body_size` 已设 10m |
| 刷新 `/result` 变 404 | SPA 回落失效 | 检查 `nginx.conf` 的 `try_files` |
| 内存告警 / OOM | OCR 峰值 | `docker-compose.yml` 已限 api 1500m；不够就升 2C8G |
| 定位很慢（>15s） | 首次请求 OCR 冷启动 | 预热失败，看启动日志 |
| 中文乱码 | 编码 | 本项目全 UTF-8，一般不会；查 `.env` 是否被存成 GBK |

## 七、备案（国内服务器必读）

**未备案域名或裸 IP 在微信内打开大概率被拦或弹风险提示。**

- ICP 备案审核 **7–20 个工作日**，加服务商初审实际 **2–3 周**
- 评审意见指出：10/27 提交，最快 11/10 左右下来，**正好卡在截止前一周，零返工余量**

**如果备案还没下来**，两条路：

1. **香港节点兜底**：免备案，约 30–50 元/月，评委访问稍慢但能开
2. **裸 IP + 端口**：国内服务器未备案的 80/443 会被拦，但换成非标端口（如 `http://1.2.3.4:8080`）通常能通

> 改端口：`docker-compose.yml` 里 `web` 的 `ports` 改成 `"8080:80"`。

```bash
# 3. 用 Python 模拟 Nginx（静态 + SPA 回落 + 反代）
#    见 docs/部署验证.md
```

已验证通过的项：

- ✅ 静态文件（index.html / assets / samples / favicon）
- ✅ SPA 回落（`/result`、`/show` 刷新不 404）
- ✅ `/health` 反代
- ✅ `/api/screenshot` + `/api/locate` 完整链路
