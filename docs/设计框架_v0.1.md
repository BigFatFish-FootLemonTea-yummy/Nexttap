## 0. 一页纸

| 项 | 内容 |
|---|---|
| 一句话定位 | 给"帮老人的人"用的即时指路工具：拍下屏幕，30 秒生成一张"下一步点这里"的卡片 |
| 初衷 | 老人不是学不会用手机，是没有人告诉他"下一步点哪里" |
| 目标用户 | **帮助者**：子女、社区网格员、银行大堂、医院导诊志愿者<br>**接收者**：老人（只读，零学习成本） |
| 核心动作 | 拍照 → 定位 → 生成卡片 → 老人照着点 |
| 与竞品的边界 | 厂商远程协助要"同品牌 + 有人实时在线"；我们只做**没人实时在线**、**跨品牌**的那一段 |
| 技术内核 | 复用自研 devSage：LangGraph StateGraph + 三阶混合检索 + HITL |
| 差异点 | 异步、跨品牌零安装、只传一张截图（不共享整屏） |
| 最大风险 | 截图元素定位准确率 < 85%，需降级为"卡片式指引" |

## 1. 问题与初衷

### 1.1 问题

老人用手机卡住的地方，往往不是"不懂这个 App 的逻辑"，而是**"这一步该点哪"**：

- 不是不会挂号，是找不到"预约挂号"藏在哪个角落
- 不是不会发视频，是不知道先点"+"还是先点"通讯录"
- 不是不会查社保，是分不清"电子社保卡"和"社保查询"

这个时刻的典型状态是：**能问的人不在身边**。

### 1.2 为什么现有方案补不上

| 方案 | 谁在用 | 老人要做什么 | 缺口 |
|---|---|---|---|
| 手机厂商远程协助 | 子女 | 点同意 | 要同品牌 / 双方装 App / **必须有人实时在线** |
| 微信视频 + 屏幕共享 | 子女 | 发起视频 | **必须有人实时在线**，且暴露全部屏幕 |
| 手机智能体（YOYO / 蓝心 / 小艺） | 老人 | 说一句话 | 复杂流程、表单、跨 App 任务做不了 |
| 社区 / 网点人工 | 工作人员 | 到店 | 覆盖时间有限，且**帮的人自己也要现学** |
| **本作品** | 帮老人的人 | 拍一张图 | — |

### 1.3 初衷（写进文档第一页）

> 老人不是学不会用手机，是没有人告诉他"下一步点哪里"。
> 我们让这句话，随时有人回答。

**非目标**：不做"教会老人"的课程体系，不做适老化平台，不做远程控制。

## 2. 目标用户与场景

### 2.1 主 persona：帮助者（B 端为主，C 端为辅）

| 角色 | 场景 | 痛点 |
|---|---|---|
| 社区网格员 | 上门帮老人办高龄补贴 | 每个 App 都要现学，教完就忘 |
| 银行大堂经理 | 老人不会用手机银行 | 重复解释同一件事，占用窗口 |
| 医院导诊志愿者 | 老人不会挂号 | 高峰期根本顾不过来 |
| 子女（C 端） | 电话里教父母 | 说不清"在哪一层菜单" |

### 2.2 次 persona：老人（接收者）

- 只负责"看"和"点"，不负责"拍"和"传"
- 端上零学习成本：打开链接 → 大字 → 一句话 → 高亮框 → 语音播报
- 不需要登录（凭 token 链接访问）

### 2.3 典型任务（评测用）

1. 微信给女儿发视频通话
2. 医院公众号挂明天上午内科号
3. 支付宝查本月社保缴费记录
4. 微信把一条消息转发给儿子
5. 手机银行查余额

## 3. 产品形态

```
帮助者端（主）                        老人端（从）
┌──────────────────┐              ┌──────────────────┐
│ 1. 拍照 / 上传截图 │              │ 大字卡片           │
│ 2. AI 定位 + 生成  │  ──链接──▶   │ 截图 + 红圈        │
│ 3. 人工确认/微调   │              │ 一句话指引          │
│ 4. 生成分享卡片    │              │ 🔊 语音播报        │
│ 5. 多步流程编排    │              │ 「下一步」按钮      │
└──────────────────┘              └──────────────────┘
```

**关键设计**：高亮圈用前端 DOM 叠加（归一化坐标 0–1000），不把圈画死在图里。
好处：可动画、可点击、可朗读、可做"放大镜"，图片不会被压糊。

## 4. 功能范围

### P0（必须，W1–W2 完成）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 截图上传 / 拍照 | 支持 jpg/png，前端压缩到长边 ≤1600 |
| F2 | 元素定位 | OCR → 候选合并 → LLM 选目标 → bbox |
| F3 | 指引生成 | 一句话（≤25 字，含方位和按钮文字） |
| F4 | 卡片生成与分享 | 生成 token 链接，微信可直接打开 |
| F5 | 老人端查看 | 大字 + 高亮 + 语音播报（SpeechSynthesis） |
| F6 | 多步流程 | 一个任务多张卡片，按「下一步」推进 |
| F7 | 拒答与兜底 | 置信度 < τ 时明确说"看不出"，给人工入口 |

### P1（W3 有余力再做）

- F8 操作路径库（标准步骤检索）
- F9 历史卡片复用
- F10 图标类目标 VLM 兜底

### 明确不做

远程控制、语音输入、多语言、学习进度/成就系统、全 App 覆盖。

## 5. 系统架构

```
┌─────────────────────────────────────────────┐
│  Vue 3 + Vite + TS + Tailwind + shadcn-vue  │
│  helper/ 老人端 elder/                       │
└──────────────────┬──────────────────────────┘
                   │ HTTPS / SSE
┌──────────────────▼──────────────────────────┐
│  FastAPI                                    │
│  ├─ vision/   OCR → 候选合并 → LLM 选择      │
│  ├─ agent/    LangGraph StateGraph          │
│  ├─ rag/      BM25 + Chroma + rerank        │
│  ├─ store/    SQLite + 本地文件              │
│  └─ mcp_server.py  (fastmcp，4 个工具)       │
└──────────────────┬──────────────────────────┘
                   │
     ┌─────────────┼─────────────┐
     ▼             ▼             ▼
 DeepSeek      Qwen-VL      RapidOCR
 (文本/推理)   (图标兜底)    (本地 CPU)
```

**部署**：单台 2C2G 轻量服务器，Docker Compose 起 `web`（Nginx 静态）+ `api`（uvicorn），同域反代避免 CORS。

## 6. 核心流程设计

### 6.1 定位管线（P0，最大风险点）

```
截图 ──▶ RapidOCR ──▶ 候选行
                        │
                        ▼
              同行合并（gap < 0.6×字高）
                        │
                        ▼
        候选列表（id + 文本 + 方位 + 尺寸）
                        │
                        ▼
        LLM（DeepSeek）选择，输出 JSON：
        {id, confidence, instruction, reason}
                        │
                        ▼
          回填 bbox → 归一化 0–1000
```

**为什么不让 VLM 直接出坐标**：坐标漂移严重、延迟 5–8s、成本高。OCR 文本 + 文本模型选择，延迟 2–3s，准确率更高。

**判定线**：hit@1 ≥ 85% 继续；70–85% 修一轮；< 70% 降级。

### 6.2 Agent 状态机（LangGraph）

```
        ┌─────────┐
        │ intake  │
        └────┬────┘
             ▼
     ┌───────────────┐
     │ parse_image   │  OCR + 候选合并
     └───────┬───────┘
             ▼
     ┌───────────────┐   confidence < τ
     │ locate        │──────────────┐
     └───────┬───────┘              │
             ▼                      │
     ┌───────────────┐              │
     │ guard         │ 涉转账/验证码 │
     └───────┬───────┘──────────────┤
             ▼                      │
     ┌───────────────┐              │
     │ retrieve_guide│  RAG（可选）  │
     └───────┬───────┘              │
             ▼                      ▼
     ┌───────────────┐      ┌──────────────┐
     │ compose       │      │ escalate     │
     └───────┬───────┘      │ 转人工/拒答   │
             ▼              └──────────────┘
        ┌────────┐
        │  done  │
        └────────┘
```

**评分对应**：`plan → act → observe → replan` 的可见链路 = Agent/工作流 8%。

### 6.3 RAG 设计

**两个库**：

| 库 | 内容 | 示例 |
|---|---|---|
| 操作路径库 | app / 任务 / 步骤序列 | 微信-发视频：我 → 服务 → … |
| 报错提示库 | 提示语 → 原因 → 解法 | "网络不给力" → 切换网络 |

**三阶检索**（复用 devSage）：

```
query ─┬─ BM25(jieba)  top20 ─┐
       └─ bge-small 向量 top20 ─┴─ RRF 融合 ─ bge-reranker ─ top5
```

**评分对应**：RAG 6%。必须有消融表（朴素 / +混合 / +rerank 的 Recall@5）。

### 6.4 安全与兜底

| 规则 | 行为 |
|---|---|
| 目标涉及转账、支付、验证码 | 不生成指引，提示"这一步请找家人或柜台" |
| 置信度 < 0.6 | 明确说"我看不清"，给重拍/转人工 |
| 页面出现"删除""注销""解绑" | 二次确认，提示风险 |
| 截图存储 | 7 天自动清理，仅本人可见 |

**评分对应**：AI 安全可控 4%。**只教不做**是红线。

## 7. 数据模型（SQLite）

```sql
sessions(id, helper_id, created_at)

screenshots(id, session_id, path, width, height, ocr_json, created_at)

locates(id, screenshot_id, goal, text, bbox_norm, confidence, model, created_at)

cards(id, session_id, step_no, screenshot_id, bbox_norm,
      instruction, audio_url, token, created_at)

guides(id, app, task, steps_json, source, updated_at)

feedbacks(id, card_id, type, note, created_at)
```

`bbox_norm` 存 0–1000 整数，前端按容器尺寸缩放，彻底避开分辨率问题。

## 8. 接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/screenshots` | 上传，返回 `image_id, w, h` |
| POST | `/api/locate` | `{image_id, goal}` → `{text, bbox_norm, confidence, instruction}` |
| POST | `/api/locate/stream` | SSE，逐步推 `ocr → locate → compose` |
| POST | `/api/cards` | `{locate_id}` → `{card_id, share_url, token}` |
| GET | `/api/cards/{id}` | 卡片详情 |
| GET | `/api/elder/{token}` | 老人端数据（免登录） |
| POST | `/api/feedback` | 老人端"没看懂/点错了" |

**MCP 工具**（`fastmcp`，4 个）：

- `locate_element(image_id, goal)` → bbox + instruction
- `search_guide(query)` → 标准步骤
- `compose_card(locate_id)` → 卡片
- `check_risk(text)` → 是否高风险

> 独立 MCP server 的价值：任何 MCP 客户端（Claude Desktop / Cursor）都能调用这套能力，答辩时可现场演示。

## 12. 风险与降级

| 风险 | 触发条件 | 应对 |
|---|---|---|
| 定位不达标 | hit@1 < 85% | **降级**：不做精确 bbox，改"截图 + 大字描述 + 大箭头" |
| 拍摄质量差 | 反光/拍歪占比高 | 加透视矫正，或引导重拍 |
| 图标无文字 | 目标在图标上 | VLM 兜底；仍不行则提示"点屏幕最下方那一排" |
| 竞品质疑 | 答辩必问 | 主动放对比表，承认边界 |
| 原创性质疑 | 复用 devSage | 文档声明 + 赛期增量 + 细粒度 commit |
| 演示翻车 | 网络/延迟 | 预置缓存结果 + 骨架屏 |

**降级后的产品仍然完整**：多模态、交互创新、社会价值三项不受影响，只是少了"精确指哪"的惊艳。
