# 5. 总结与展望

---

## 5.1 我们做了什么

一句话：**给"正在帮老人的人"做了一个 30 秒出结果的即时指路工具。**

拆开看是四件事：

| 能力 | 实现 | 实测 |
|---|---|---|
| **看懂屏幕** | OCR 把像素变成候选元素 | 平均 21 个候选/屏 |
| **听懂需求** | 大模型从候选里选目标 | hit@1 98.2% |
| **找到路径** | 三阶检索匹配 30 条任务链 | Recall@5 98.4%（留出集 61 条） |
| **给出指引** | 叠圈卡片 + 大字 + 语音 | 时延 p50 2.7s |

---

## 5.2 三个关键判断

### 判断一：主用户是帮助者，不是老人

这个判断让"老人自己不会截图"这个死结直接消失。

如果主用户是老人，产品第一天就会卡在"怎么教老人截图"上。
换成帮助者后，产品形态变成**双屏**——帮助者举手机，老人低头点自己的。

**这是整个项目最省钱的一个决策**：它没有增加任何技术难度，
但消除了一整类无法解决的问题。

### 判断二：本质是"一张能记住的图"

老人看完卡片要切回微信去点，卡片就没了。所以：

- 信息密度压到极限（≤20 字）
- 语音要**先播再让他切走**
- 全屏模式屏幕常亮

这个"记住 vs 切走"的约束，比再加一个功能更能体现产品想清楚了。

### 判断三：失败要诚实

**宁可说"看不清"，也不硬猜。**

因为猜错了老人会点错——在转账、验证码这类场景下，点错的代价远大于不点。

这条判断落到三个地方：

1. 模型没有合适候选时返回 `null` → 422
2. 检索域外时返回空 → 提示"没有匹配到标准路径"
3. 置信度低时标记 `low_confidence` → 提示重拍

---

## 5.3 做对了什么

### 1. 数据先于算法

| 阶段 | Recall@5 |
|---|---|
| 起点（模板 aliases） | 26.5% |
| **补同义词（纯数据工作）** | **47.1%**（+20.6） |
| 上向量 + RRF | 79.4%（+32.3） |

**纯数据工作的收益，和真正的算法升级是同一量级。**

这个发现纠正了团队最初的路径——原本打算直接上向量检索，
实测后才发现"先修数据，再改算法"才是对的。

### 2. 分层让演进成为可能

`guide.py` 只依赖标准库，不 import OCR、不 import 模型。

**收益**：检索算法从纯词面换成三阶检索，14 项单测一行没改，
MCP 进程不需要加载 600MB 的 OCR 模型。

### 3. 主动去水分

发现 goal 泄漏后，主动把 82 条改成口语并重跑，数字从 91.5% 降到 89.6%；11/06 进一步换掉整套评测集（110 图 / 110 用例，step=1 全部口语），新集 hit@1 **98.2%**。

**这 1.9 个点是主动去掉的。** 主动交底比被评委问出来强。

### 4. 指标成对看

初期只报 Recall@5，掩盖了"域外查询乱返回"的严重 bug
（一个返回全部 30 条的系统，Recall@5 = 100%）。

后来补了拒识率测试，才发现问题。

## 5.4 做错了什么

诚实记录，因为这些比成绩更有参考价值。

### 1. 自己出题、自己答题、自己判卷

检索评测集由实现者手写，同时实现者又在改同义词表。
独立审查发现：新增 23 条同义词里，**14 条的 key 字面来自评测集 query**。

量化后：20.6 个点里有一部分是虚的。

**教训**：评测集必须独立于优化过程。正确的做法是真人访谈采集，
这也是为什么本文档主指标用留出集（98.4%，更保守）而不是盲写集（99.3%）。

### 2. 只看一个指标

见 5.3 第 4 点。

### 3. 没有尽早拉独立验证

RAG 那套数字在提交前没有经过任何外部校验。
派了三个子智能体独立审查后，**当天就发现了两个真 bug**：

- `_index_text` 里的恒真条件
- hybrid 模式丢失域外拒识（域外查询也返回结果）

如果早点做，这些问题不会进仓库。

### 4. 恒真条件这类低级错误

```python
if a.startswith(("怎么", "我要", "帮我")) and a[2:] in (name, a[2:]):
```

`a[2:] in (name, a[2:])` 里 `a[2:]` 恒等于自己，条件永远为真。
行为碰巧对（模板 alias 本来都该剔），但意图与实现不符。

**教训**：这类错误读代码时很难发现，需要有人专门审。

## 5.6 展望

### 近期（赛期内可做）

1. **多步预热落地**：第 2 步之后不用重新截图，4 步任务从 11 秒降到 3 秒
2. **置信度可解释化**：用 top1/top2 分差替代模型自报的 confidence
3. **历史卡片复用**：LocalStorage 存最近 5 张卡片，直击"教完就忘"

### 中期（产品化）

1. **扩展场景**：从 3 个（医院/政务/微信）扩到 10 个高频场景
2. **B 端采购路径**：社区、银行、医院的采购决策链
3. **离线模式**：小模型 + 本地检索，完全断网可用

### 长期（这件事的真正意义）

这个产品解决的不是"老人不会用手机"，而是**"没有人有时间一步步教"**。

它的终局不是替代人，而是**把人的时间从重复解释里解放出来**——
网格员不用再说第 100 遍"这个码在哪儿点"，
他只需要拍一张照，把手机举起来。

> "老人不是学不会用手机，是没有人告诉他下一步点哪里。"

这句话是起点，也是这个项目全部设计的依据。

## 5.8 结语

22 天，2 个人，从 0 到 98.2%。

这个数字不算惊艳——它意味着每 10 次里还有 1 次会失败。
但我们选择把它真实地报出来，而不是靠泄漏数据做到 95%。

**因为我们做的这个产品，本身就是关于"诚实"的**：
告诉老人"我看不清，请重拍"，比硬指一个错的地方要好。

如果文档里只能留下一句话，我希望是这句：

> **把能确定的做确定，把不确定的诚实说出来。**
