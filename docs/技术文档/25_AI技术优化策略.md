## 2.5.1 优化总览：先修数据，再改算法

本项目做过一次重要的方向纠偏，值得先说。

最初计划是"上向量检索、上 rerank、做三阶融合"——这是技术上最"标准"的路径。
但实测发现：**在数据质量没解决之前，调算法是白费力气。**

### ⚠️ 口径说明（重要）

**下面这张表所有数字都统一了评测口径**：`min_score=0`、`top_k=5`，
即所有配置都返回满 5 条候选。

> 为什么强调这个：早期版本的消融表里，`lexical` 带着 `min_score=0.42` 跑，
> 导致 68 条里有 **24 条返回空结果**，R@5 的数学上限被压到 64.7%；
> 而 `hybrid` 当时不设阈值、永远返回满 5 条。**两者根本不可比**，
> 把真实增益放大了约 2.8 倍。这个问题是独立复现时发现的，已修正。

### 同口径消融表（原评测集 68 条）

| 阶段 | 动作 | Recall@1 | Recall@5 | MRR |
|---|---|---|---|---|
| 起点 | 纯词面，**无同义词词典** | 30.9% | 54.4% | 0.399 |
| 第 1 步 | **补同义词词典**（不改算法） | 38.2% | 67.6% | 0.493 |
| 第 2 步 | 上向量召回 + RRF | 44.1% | 72.1% | 0.564 |
| 第 3 步 | 再叠 rerank（仅离线） | 45.6% | 77.9% | 0.598 |

**真实增益**：
- 补词典：R@5 **+13.2 点**（54.4 → 67.6）
- 向量 + RRF：R@5 **+4.5 点**（67.6 → 72.1），R@1 **+5.9 点**
- rerank：R@5 +5.8 点，但单次耗时从 20ms 涨到 645ms，**线上不启用**

**结论修正**：数据工作的收益（+13.2）确实大于算法升级（+4.5），
这印证了"先修数据再改算法"的判断。但**早期版本宣称的"算法涨 32.3 点"
是被错误口径放大的，真实增益远小于此。**

### 留出集上的同口径结果（52 条，更可信）

| 配置 | Recall@1 | Recall@5 | MRR |
|---|---|---|---|
| 纯词面 | 28.8% | 63.5% | 0.423 |
| + 向量 + RRF | 44.2% | 75.0% | 0.557 |
| + rerank（仅离线） | 55.8% | 88.5% | 0.687 |

留出集上向量召回增益更明显（R@5 +11.5 点），且 rerank 在留出集上
提升显著（+13.5 点）——说明 rerank 对未见过的话术更有效，
但延迟代价决定了它只能离线用。

## 2.5.2 优化一：数据质量（+13.2 个点）

### 问题：aliases 是模板拼接的

`data/rag/paths.jsonl` 里 120 条任务链，每条有 3–4 个 aliases。但它们是模板生成的：

```json
{"name": "儿子的微信",
 "aliases": ["儿子的微信", "怎么儿子的微信", "我要儿子的微信", "帮我儿子的微信"]}
```

306 条 alias 里，**306 条都是这种产物**——去掉"怎么/我要/帮我"前缀后完全重复，
对检索的贡献是 **0**。

### 修法：补真实口语同义词

建立"老人说法 → 界面用词"的映射表（`guide.py` 的 `_SYNONYMS`）：

| 老人会说 | 界面上的字 | 字面重合 |
|---|---|---|
| 退休金 | 养老保险 | **0** |
| 交税 | 粤税通 | **0** |
| 零花钱 | 红包 | 1 字 |
| 化验单 | 检验检查 | **0** |
| 大夫 | 医生 | **0** |
| 政务 | 粤省事 | **0** |

这些映射的字面重合度极低，**纯字面匹配永远对不上**，必须人工补。

### 效果

同口径下 Recall@5 从 54.4% → 67.6%，**涨 13.2 个点，没有改一行算法。**

### ⚠️ 一个必须说明的方法论问题

这批同义词是**看着评测集补的**——有 14 条 key 字面出现在评测集 query 里。
独立审查指出这是"自评循环"，量化后：13.2 个点里有一部分是虚的。

**正确的做法**（尚未完成）：同义词应该来自真人访谈，
而不是来自评测集。这也是为什么本文档把"留出集"数字作为主指标。

## 2.5.3 优化二：三阶检索（+4.5 个点，但 R@1 涨 5.9 点）

### 2.5.3.1 词面召回的三个技巧

纯 `str in str` 匹配在中文短句上几乎无效，做了三件事：

**（1）去口语填充词**

```python
_FILLERS = ("我想", "我要", "帮我", "怎么", "可以", "能不能", "一下", "这个", "那个", ...)
```

"我想看看儿子" → 去掉填充词 → "看儿子"。剩下的是关键词。

**（2）二字组重合度**

中文短句里编辑距离偏保守。"退休金" vs "养老金"的 `SequenceMatcher` 只有 0.33，
但它们的二字组 `{退休, 休金}` vs `{养老, 老金}` 有"金"字重叠。

```python
def _sim(a, b):
    seq = SequenceMatcher(None, a, b).ratio()
    overlap = len(bigrams(a) & bigrams(b)) / min(len(bigrams(a)), len(bigrams(b)))
    return max(seq, overlap)   # 取较大者
```

**（3）分层权重**

不同字段的可信度不同：

| 字段 | 权重 | 理由 |
|---|---|---|
| aliases 命中 | 0.9 | 直接对应 |
| name 命中 | 0.9 | 直接对应 |
| name 相似 | 0.95 × sim | 略降 |
| steps[].target 命中 | **0.6** | 像"点确定"这种通用词会到处命中 |

### 2.5.3.2 向量召回

**模型选择**：`BAAI/bge-small-zh-v1.5`

| 候选 | 维度 | 大小 | 选择 |
|---|---|---|---|
| bge-small-zh-v1.5 | 512 | 90MB | **采用** |
| bge-base-zh | 768 | 400MB | 内存翻倍，收益不明 |
| multilingual-e5-large | 1024 | 2.2GB | 2C4G 放不下 |

**索引文本的构造**（`_index_text`）：

```
name + aliases（去模板前缀）+ steps[].target
```

例：
```
"儿子的微信，确认当前聊天，点视频通话，选视频通话"
```

这样向量同时看到"任务叫什么"和"中间要点哪些按钮"。

**部署方式**：`fastembed`（ONNX Runtime），常驻内存约 120MB。
不用 torch 版（600MB+），因为要和 OCR 抢内存。

### 2.5.3.3 RRF 融合

```python
score(d) = Σ weight_i / (k + rank_i(d))     k = 60
```

**为什么不用分数加权**：词面是 0–1 相似度、向量是余弦距离，量纲不同。
归一化方式本身会引入偏差，权重也难调。RRF 只看排名，无需调参。

**实测贡献**（同口径）：融合后 Recall@1 从 38.2% → 44.1%（+5.9 点），
Recall@5 从 67.6% → 72.1%（+4.5 点）。

> 注：早期版本报的"R@5 从 47.1% → 79.4%"是错误口径（lexical 带阈值、hybrid 不带），已废弃。

## 2.5.4 优化三：域外拒识（不提升召回，但避免错误）

### 这是一个"负向优化"，但同样重要

初版 hybrid 有个严重 bug：域外查询也返回结果。

```
"我想买火车票"   → 返回 3 条无关任务链，分数全是 RRF 地板分 0.016
"今天天气怎么样" → 同上
```

这不只影响体验——它让 MCP 的 `search_guide` 永远拿不到
"没有匹配到标准路径"的提示，客户端会拿着 3 条无关结果继续执行。

### 三轮迭代（详见 2.4.4）

| 轮次 | 方案 | 域外误召 | 原集 R@5 | 留出集 R@5 |
|---|---|---|---|---|
| 1 | 向量阈值 ≥0.45 | 3/8 | 80.9% | 76.9% |
| 2 | 加"字面必须有交集" | **0/8** | **58.8%** | 50.0% |
| 3 | **阈值 + 相对领先** | **0/8** | **79.4%** | **71.2%** |

第 2 轮是典型的过度矫正：域外全拒了，但砍掉 14 条正确答案。

### 最终判据

```python
top_sim >= 0.55  and  (top1 - top5) >= 0.02
```

**核心洞察：域外查询的特征不是"分数低"，而是"分数平"。**

| 查询 | top1 | top5 | 分差 | 判定 |
|---|---|---|---|---|
| "给孙子点零花钱" | 0.535 | 0.47 | 0.065 | 域内 ✓ |
| "我要打游戏" | 0.524 | 0.512 | 0.012 | 域外，拒识 ✓ |

两者 top1 只差 0.011，但**分差**差 5 倍。这才是可用的信号。

## 2.5.5 优化四：rerank 的取舍（结论：线上不用）

### 实测

| 配置 | 原集 R@5 | 留出集 R@5 | 单次耗时 |
|---|---|---|---|
| hybrid | 72.1% | 75.0% | ~20ms |
| + rerank | 77.9% | 88.5% | ~645ms（P90 2.6s） |

**收益**：+1.5 / +9.6 个点（留出集上更明显）
**代价**：耗时涨 38 倍

### 决策：只在离线跑消融表

理由：

1. **3.8s 不可接受**。定位链路本身已经 2.7s，加上 rerank 会突破 C4（≤5s）
2. **内存代价**：bge-reranker-base 约 1.1GB，2C4G 上和 OCR 抢内存
3. **评审意见早有预判**："线上不跑 rerank，只在离线做消融表——RAG 6% 要的是消融数据，不是线上延迟"

这条决策体现了本项目的取舍原则：**评分项要的是"你做过对比实验"，
不是"你线上跑得动"**。

## 2.5.6 优化五：定位链路的优化

### 5.1 减少模型调用次数（多步预热）

一个任务链有 1–4 步。如果每步都重新截图 + 调模型，一个"给儿子发视频"
要 3 次完整调用 ≈ 8 秒。

**优化**：命中任务链后，`compose_card()` 返回"下一步是什么"，
第 2 步之后可以直接预判，不需要重新截图。

```python
compose_card(text, instruction, task_id, step)
  → {"current_step": ..., "next_step": {...}, "has_next": True}
```

> 当前状态：数据结构已就绪，前端尚未接入完整的多步预热流程。
> 这是 W3 的改进项。

### 5.2 Prompt 优化

优化前的 prompt 让模型输出坐标，实测漂移严重。优化后：

- **只让模型输出候选编号**（整数），坐标由 OCR 提供
- **候选列表带方位描述**（"屏幕上方靠左"），帮助区分同名元素
- **instruction 限 20 字**，且要求含方位

效果：定位准确率 hit@1 从初版提升到 **89.6%**（164 条用例）。

### 5.3 置信度与降级

模型自报的 `confidence` **是不校准的**——这是评审意见点名的风险：

> "τ=0.6 大概率对不上实际准确率，答辩必问'你的置信度怎么来的'"

当前实现：`MIN_CONFIDENCE=0.60` 作为阈值，低于则标记 `low_confidence`。

**改进方向**（尚未实现）：换成可解释量——

- top1/top2 候选的**分差**
- 3 次采样的**一致性**
- 检索命中强度

> 这与 2.5.4 里"域外拒识用分差而非绝对值"是同一个思路：
> **相对量比绝对量可靠。**

## 2.5.7 优化效果汇总

### 定位（164 条用例，47 张图）

| 指标 | 数值 |
|---|---|
| hit@1 | **89.6%**（147/164） |
| 95% 聚类置信区间 | [85.2%, 93.8%] |
| step=1（用户口语） | 86.6%（103/119） |
| step≥2（路径已定） | 97.8%（44/45） |
| 整链成功率 | 87.6%（92/105） |
| 时延 p50 / p90 | 2663ms / 4031ms |

### 检索

| 集合 | Recall@5 | MRR |
|---|---|---|
| 原评测集（68，有自评污染） | 72.1% | 0.564 |
| **留出集（52，相对干净）** | **71.2%** | 0.581 |

### 一个必须说明的优化：清洗 goal 泄漏

定位指标曾经是 91.5%，但审计发现 **119 条 step=1 用例里有 82 条的 goal
直接写着目标按钮的文字**（goal「点公积金」，真值框里就是"公积金"），
模型做字符串匹配就能命中。

清洗后降到 **89.6%**。

**这 1.9 个点是主动去掉的水分。** 主动交底比被评委问出来强。

## 2.5.8 优化方法论小结

本章的五个优化，按"性价比"排序：

| 优化 | 成本 | 收益 | 结论 |
|---|---|---|---|
| 补同义词数据 | 半天 | +13.2 点 | **最高性价比** |
| 向量召回 + RRF | 1 天 | +4.5 点（R@1 +5.9） | 核心算法升级 |
| 域外拒识 | 半天（三轮返工） | 不涨召回，但避免错误 | 必须做 |
| Prompt 优化 | 持续 | 定位 89.6% | 长期迭代 |
| rerank | 半天 | +1.5 点，慢 38 倍 | **线上不用** |

**三条可复用的经验**：

1. **先修数据再改算法**——数据问题的收益常被低估
2. **相对量比绝对量可靠**——拒识用分差、置信度也该用分差
3. **指标要成对看**——只看 Recall 会掩盖"乱返回"，必须同时看拒识率

第 3 条是踩过的坑：初版只报 Recall@5，结果"返回一堆垃圾"的 bug
在指标上完全看不出来（一个返回全部 120 条的系统，Recall@5 = 100%）。
